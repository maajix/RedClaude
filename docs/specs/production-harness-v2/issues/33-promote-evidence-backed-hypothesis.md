# 33 — Promote an evidence-backed Hypothesis

**What to build:** Turn one hunter proposal into a canonical, deduplicated Hypothesis only when its subject, Property class and supporting Observations are valid for the Program.

**Blocked by:** 21 — Promote a recon Mission into typed Surface.

**Status:** ready-for-agent

- [ ] A proposed Hypothesis names one canonical subject, Property class, relevant Identity cell and structured rationale without claiming execution.
- [ ] Evidence edges reference immutable Observations with polarity and baseline, variant or control role.
- [ ] Runtime promotion verifies Program reachability, vocabulary, provenance and duplicate identity before creating canonical rows.
- [ ] Semantically duplicate proposals converge on one Hypothesis and retain distinct valid evidence edges.
- [ ] Unsupported, foreign, missing-provenance and vocabulary-invalid proposals remain rejected staging outcomes.
- [ ] Only the runtime may transition the Hypothesis from proposed to testable, and no proposal can mark it testing or terminal.
